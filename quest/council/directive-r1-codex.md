# Codex gpt-6-astra — directive.md round 1 critique (2026-09-20)

CHANGE — 1. Preserve demo's distinct substitution policy. 2. Preserve evaluate's absent-key and browser-fallback behavior. 3. Specify reproducible baseline, provider-attempt, and accounting verification.

The directive has clear boundaries and review responsibilities, but its resolver cannot preserve all current route behavior. Three issues block approval.

1. Separate fallback permission from initial-provider substitution. Demo without a grant always retains body.provider, including when allowFallback is true (demo:42–47). The proposed server contract instead substitutes configured[0] when that provider is unconfigured. This changes the provider passed to claimEvaluation and assessEvidence, and potentially the fallback diagnostic. It exceeds intent §5's two changes. Add an explicit substitution policy input and preserve this path's requested provider with a possibly absent key. Keep the new refusal for fallback-disabled requests. The hostedAdmin browser-over-server merge is correctly identified; require tests proving browser values, including empty strings, override server fallback values without replacing the primary key.

2. Preserve evaluate's missing-key behavior. The current route does not reject a missing caller key or an empty hosted server configuration before assessEvidence. assessEvidence can return a deterministic no-evidence result without credentials; with fallback enabled, browser fallback credentials can still succeed. Part 4.1's missing_caller_key and no_provider_configured failures, combined with Part 4.2's error mapping, introduce additional early failures. The successful resolution type must accommodate an absent primary key where current policy permits it. Specify existing-path behavior and error precedence rather than treating every missing credential as a route-level refusal. Also keep fallback-header parsing conditional on fallback permission; unconditional parsing would newly reject malformed headers that are currently ignored.

3. Make verification measure route policy, not merely resolver consistency. Part 5.4 cannot defensibly compare copied inline code against full Resolution objects: current code has no substituted field or matching failure union, and the Cartesian product includes policies that routes cannot reach. Define route-specific adapters, reachable fixtures, normalized observable outputs, and classifications separating the two intended fixes from preservation failures. Cover grant/admin status, browser fallback overrides, absent and whitespace-only credentials, and fallback order. Preserve an executable baseline harness in an identified historical commit and provide its exact reproduction command; checkout of 50fa2dc alone cannot reproduce the proposed violation count.

Intent §9 also promises scripted provider-attempt measurements and an accounting-order assertion. Neither is implemented by the prescribed module tests or one manual request per route. Assign a concrete mocked verification method. Checking unchanged call lines does not prove unchanged execution: the new demo refusal bypasses claimEvaluation. Explicitly resolve whether that bypass is the intended consequence of refusal while preserving charge-before-attempt ordering on accepted requests.

For cuts and clarity, scope Y2 to the three migrated routes rather than all src/app/api. Remove the forbidden quest/agent-notes.md option or explicitly exempt documentation. Replace the arbitrary five-second/five-minute yardsticks with reproducible checks. The labelled empty handoff template is appropriate.
